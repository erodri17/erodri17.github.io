I'm Elmer Rodriguez. I work in operations and build the tooling that keeps
day-to-day work moving: PowerShell scripts, Windows desktop utilities and the
written procedures that go with them.

Most of what I build starts the same way. A task is being done by hand, it has
to be right every time, and the steps live in someone's head. I turn the steps
into a tool, make the tool show what it is about to do before it does it, and
write down how to run it.

## How I work

- **Automate the repeatable.** If a task is done the same way every week, it
  should be a script with logging and clear error messages, not a list of
  manual steps.
- **Preview before changing anything.** Tools that rename, move or edit files
  show the result first and wait for an explicit go-ahead. Where it makes
  sense, they keep a journal or a backup so the change can be undone.
- **Keep tools small.** One tool, one job. A utility that does a single thing
  well is easier to trust and easier to hand over.
- **Write it down.** A process is finished when someone else can run it from
  the documentation alone.

## What I use

- **PowerShell** for automation and for the desktop tools themselves.
- **Windows Forms** and SAPIEN PowerShell Studio for the user interfaces.
- **CSV and XML** for data and configuration, so files stay readable without
  special software.
- **Git and GitHub** for version control and review.
